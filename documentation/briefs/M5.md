### 1. `rules/folds.py` (tkinter-free, ezdxf-free — architecture matrix green)

```python
def validate_fold_against_contours(fold: Seg, primitives, eps) -> list[str]
    # SPEC §11.3 case 5: distance from the fold SEGMENT to every contour
    # LINE/ARC edge must exceed eps; one warning string per violating edge.
    # Format matches dxf_io/load._fold_contour_warnings (pin exact text in
    # the session log; reuse that helper's wording so the two surfaces
    # agree): "fold {eid} runs within {eps} mm of contour edge {other_eid}"
    # Warnings NEVER silently assume §4.5's rule (no auto-undesignation).

def resolve_folds(primitives, dogbones, fold_eids, eps) -> list[Trim]
    # §11.6 deterministic rule, per dogbone circle in dogbones order:
    # for each designated fold (Seg) whose supporting line crosses the
    # circle (line-circle intersections, geomops):
    #   - idempotent by construction: an endpoint already on the arc
    #     (dist(endpoint, center) == r within eps) -> SKIP that endpoint
    #   - extend along line direction to the FIRST circle intersection,
    #     only if within max 2x deletion window (2 * 4 * tool-diameter...
    #     pin: reach = 2 * WINDOW_FACTOR * 2 * r); else unchanged + warn
    #   - trim at first circle entry from the KEPT side (the endpoint
    #     whose kept portion's interior misses the circle; a fold crossing
    #     the circle with both endpoints out trims the NEARER entry from
    #     each side? NO — pin: a fold is designated with two endpoints;
    #     each endpoint resolves independently; a both-sides crossing
    #     yields TWO trims... AMEND: Trim is per-eid; one Trim per fold
    #     eid — resolve BOTH endpoints, return ONE Trim with the pair;
    #     both already on-arc -> no Trim (idempotency fixture).
```

**Signatures are CONTRACTS §2/§3-named already; pin the normative block at
sprint start (no contract change).** All decisions reference `eid` only
(AGENTS #3); no `==` on coordinates — `geometry/tolerances.py` values passed
explicitly (AGENTS #2).

### 1. Mode toggle + selection (`ui/fold_panel.py`)

- `FoldPanel` + `FoldWorkflowUI`-style seam (thin tkinter shell ONLY —
  screen↔world + events → `rules` calls; no geometry in `ui/`, ADR-006):
  - **mode toggle** button (fold-designate mode vs corner mode);
    Esc/right-click exits fold mode cleanly (no partial state).
  - **click toggles** a designated fold; **shift-click toggles** too
    (identical semantics, both directions);
  - **box/marquee select**: drag ≥5 px = box (CONTRACTS §3 note); below
    threshold = click (toggle the picked fold only). Straight LINEs only
    (§4.5) — arcs/circles/points/text never designated;
  - **live badge**: `7 of 9 straight lines designated` — count updates on
    EVERY change (click, shift-click, box, load, undo/restore);
  - **fold-color rendering**: designated folds draw in the fold color
    (theme key; ACI-7-derived light tone on the dark canvas);
  - **validation warnings surface**: on designation,
    `validate_fold_against_contours` results go to the status line
    (non-blocking; the §11.3 case-5 load stub stays empty-by-construction
    per its docstring — designation time is the seam);
  - designation writes `model.state.fold_eids` (exists since the M2
    scaffold); folds are protected in `place_corner` (already wired);
  - **auto-preselect**: at load, layers matching the editable pattern
    list (case-insensitive contains `bend|fold|centerline` — ISSUE-003
    defaults) auto-designate. Fires ONCE per load; user changes after
    that are authoritative (a later Open re-fires for the new document).
    Pattern list editable (GUI field, persisted per session in-memory
    only).
