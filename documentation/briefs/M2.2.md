2. **Adjacency metric consistency.** `geometry/adjacency.py` pairs attachment points with box-proximity (`abs(dx) <= eps and abs(dy) <= eps`) while `rules/engine.py` `_shared_point` uses Euclidean-in-x/y per-axis too but the cascade's portion tests use `point_seg_dist` — unify the pairing metric to Euclidean distance (`math.hypot(dx, dy) <= eps_coincide`) so adjacency and contact never disagree by a factor of √2. Regression: a probe fixture with two entities meeting at a diagonal (√2·eps/2, √2·eps/2) offset — currently adjacent under box, must NOT be under Euclidean; assert the cascade no longer counts it.

3. **resolve_edge: walk the chain from the seed, not the seed's midpoint.** The mathematician's X-crossing defect: `resolve_edge` re-derives the run via `promoted_edge_at(seed-midpoint)`; if a non-collinear entity passes within EPS_PICK of that midpoint the pick returns the wrong entity and the engine falsely refuses UNKNOWN_EDGE (probe-confirmed on a T-pair both directions). Fix: after the iterative seed lookup, call `chain_run(primitives, seed, eps_coincide)` directly and drop the pick step. Keep the seed-membership guard. Regression: an X-crossing at the seed midpoint and a stub crossing a bar at its midpoint both resolve correctly.

4. **chain_run canonical direction from the run extent.** The two-ids defect the mathematician probe-confirmed: the canonical direction currently keys off the CLICKED seed's direction sign (`dx > 0 or (dx == 0 and dy > 0)`), so an alternating-micro-drift near-vertical run mints different ids from different clicks. Fix: compute the run's extent vector first (current walk, symmetric over both projections), then set the canonical direction from the EXTENT (`hi_pt - lo_pt`), snapping to the dominant axis when |dx| ≈ |dy| within EPS_CONSTRUCTION. Regressions: the alternating-drift fixture minting ONE eid from clicks on both members; add it to the twin-sync corpus.
