## Decisions made this session

1. **`TrimFSM` field/method name collision (bug found + fixed):** dataclass field
   `click_world: Pt | None` shadowed the `click_world(...)` method → `TypeError: 'NoneType'
   object is not callable`. Renamed field to `last_click`. The FSM now also re-proposes
   (`ports.propose(last_click, picked_eid)`) inside `confirm()` so a model change between pick
   and confirm cannot apply a stale result.
2. **FakePorts fixtures carry promoted eids:** `pick_edge` returns the promoted run, so
   fixture Segs must carry `promoted-L1` / `promoted-S1` as their eid, not the member eid —
   tests updated to mirror `promoted_edge_at` semantics (ADR-012 note for future tests).
3. **Stray-first ordering is observable:** the STRAY rule fires BEFORE any trim proposal —
   demonstrated in the drive (isolated designated `STRAY` gets a whole-run deletion proposal).
4. **Drive fixture iterations (documented so nobody "fixes" them back):**
   - `T2` line at x=18 beat the intended `T` at x=10 as "closest" for L1's endpoint (dist 2 vs
     10) — correct engine behavior; replaced the extend target with `POINT(13,80)`.
   - The FOLD extend fixture initially had the fold isolated → stray rule deleted it instead of
     extending (stray-first again); attached `WALL2` at (0,80) to make it non-stray.
   - NO_TARGET case needed its own minimal 2-entity model (any scene with `T` nearby always has
     a candidate), driven via `panel.model = model2` swap.
   - Undo: **3 confirms = 3 pushes = 3 undos** (ADR-001 one-push-per-Confirm unchanged); a
     single `stack.undo()` restored only the last edit.
5. **Naming:** milestone id `M-TRIM` (ADR-025 title), session log `2026-10-07-M-TRIM.md`,
   drive flag `--trim`, row placed between M5b and M6 in ISSUES.md.
