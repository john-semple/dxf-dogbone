```python
# rules/folds.py — pure, imports geometry only (architecture matrix green).
FOLD_REACH_FACTOR = 2.0  # extend cap = 2 * WINDOW_FACTOR * 2 * r
                        # (WINDOW_FACTOR=4.0 from rules.engine; reach = 16*r)

def validate_fold_against_contours(fold: Seg, primitives, eps) -> list[str]
    # SPEC §11.3 case 5 wording reused verbatim from
    # dxf_io/load._fold_contour_warnings so the two surfaces agree:
    # "fold {eid} runs within {eps} mm of contour edge {other_eid}"
    # One string per violating contour edge; non-blocking; never auto-undesignates.

def resolve_folds(primitives, dogbones, fold_eids, eps) -> list[Trim]
    # SPEC §11.6 deterministic rule. ONE Trim per fold eid whose supporting
    # line crosses any dogbone circle; both endpoints resolve independently.
    # Idempotent by construction: an endpoint already on the circle
    # (dist(endpoint, center) == r within eps) -> SKIP that endpoint.
    # Extend along line direction to the FIRST circle intersection, only if
    # the intersection lies within FOLD_REACH_FACTOR * WINDOW_FACTOR * 2 * r
    # of the endpoint (reach cap); else unchanged + warn (the warning is the
    # caller's responsibility — resolve_folds returns Trims only; the export
    # stage surfaces the warn-on-out-of-reach via ExportResult.warnings).
    # Trim at first circle entry from the KEPT side: the kept side is the
    # side whose kept portion's interior misses the circle (the same
    # §11.4 post-condition the rebuild uses); for a fold whose BOTH endpoints
    # are outside the circle (a both-sides crossing), each endpoint trims to
    # its NEARER entry along the line. Both endpoints already on-arc within
    # eps -> no Trim for that fold (idempotency fixture).
```

Trim semantics per ADR-024(c) / CONTRACTS §1: `Trim.old` / `Trim.new` =
`(Pt, Pt)` endpoint pairs (Seg semantics; ADR-015(d)).

## Decisions (this session)

1. **`FOLD_REACH_FACTOR` constant** lives in `rules/folds.py` as a module
   constant (not in `geometry/tolerances.py` — it's a fold-rule factor, not
   a coordinate tolerance). Formula pinned: `reach = 2 * WINDOW_FACTOR *
   2 * r` (= 16·r) per ADR-024(c) / brief §1. `WINDOW_FACTOR` is imported
   from `rules.engine` (4.0) so the two stay coupled.
2. **`validate_fold_against_contours` measures point-to-SEGMENT distance**
   (via `geometry.geomops.point_seg_dist`), not just endpoint distance — a
   fold overlapping a contour edge mid-segment is the §11.3 case-5 case.
   The load-time stub measures only endpoint distances (it stays
   empty-by-construction per its docstring; M5b surfaces designation-time
   warnings via this function — different shape, same wording).
3. **`resolve_folds` iterates dogbones in order, fold eids sorted** —
   deterministic (SPEC §11.6). For each (fold, dogbone) pair where the
   fold's supporting line crosses the circle, both endpoints resolve
   independently against THAT circle; a fold crossing two dogbone circles
   resolves against the nearer intersection per endpoint (the FIRST entry
   from the kept side). The trim/extend endpoint is the FIRST circle
   intersection along the line direction from the endpoint's kept side.
4. **Out-of-reach warning text** pinned (export-stage surface):
   `"fold {eid} endpoint out of reach (extend cap = {reach:.3f} mm); left unchanged"`.
5. **Export `ExportResult`** = `(warnings: list[str], audit_summary: str,
   deleted_entity_count: int)` per CONTRACTS §3. `deleted_entity_count` is
   always 0 in M5a (no entity deletions in the fold stage — only Trims);
   M6's audit gate may surface nonzero if the audit removes entities.
6. **Audit pre-check** runs `ezdxf.audit` on the deep copy before save;
   non-clean audit surfaces an `audit_summary` string and the save still
   proceeds (M6 owns the strict refuse gate; M5a's job is to RUN the audit
   and report — the brief says "stub the M6 seam: audit runs; save may be
   exercised via a temp file; the M6 dialog wiring is NOT M5a scope"). A
   clean audit yields `audit_summary = "clean"`.
7. **Export writes to a temp dir in tests** (pytest `tmp_path`); the M6
   dialog supplies the real out_path. Output version = `$ACADVER` from the
   header (CONTRACTS §3 + SPEC §11.3 case 2: output version == input
   version).

### Decisions discovered during implementation

8. **Inside-endpoint trim kept-portion direction.** An endpoint STRICTLY
   inside the circle (`dist < r - eps`) has no "p's side of the cut" — the
   kept portion is towards the OTHER (outside) endpoint: `cand → q`, not
   `p → cand`. An endpoint ON the circle (`dist == r` within eps) is
   idempotent (already at a valid position); `p_in` uses strict `< r - eps`
   so on-arc endpoints don't get treated as inside. The §11.4 post-condition
   applies to the kept portion either way.
9. **No-flip guard retained.** A fold entirely on one side of the circle
   must not extend the FAR endpoint through the near endpoint to reach the
   circle. The guard rejects candidates whose projection crosses past the
   other endpoint's projection. (This was temporarily removed during
   implementation then restored after the both-endpoints-on-same-side
   defect surfaced.)
10. **`validate_fold_against_contours` uses segment-to-segment distance**
    (`_seg_seg_dist`), not just fold-endpoint-to-contour — a fold collinear
    with / overlapping a contour edge mid-segment is the §11.3 case-5 case
    and must warn even when both fold endpoints are far from the contour
    segment's projection. The load-time stub stays endpoint-based
    (empty-by-construction per its docstring); M5b surfaces designation-time
    warnings via this function.
11. **`out_of_reach_warnings` computed on ORIGINAL endpoints** (before
    trim/extend), not the post-trim copy — a fold whose near endpoint is
    within reach but whose far endpoint is beyond the cap must warn about
    the far endpoint's original position. The export stage calls
    `out_of_reach_warnings` BEFORE `_apply_trims`.
12. **Export sets `$INSUNITS=4`** on the output doc (ezdxf's `new()` defaults
    to 6; the loader refuses anything other than 4 — round-trip must stay
    in mm per SPEC §11.3 case 1 / ADR-005).
13. **Re-export idempotency test re-designates the fold eid** after reload
    (the loader sets `fold_eids=set()`; M5b's auto-preselect would re-pick
    the FOLD_LINES layer — here the test designates manually to isolate the
    engine idempotency).
