## What happened

1. M7 maturity discussion with the user. Product decisions (user, 2026-10-07,
   in order made):
   - 3D viewer value is the FOLDED view (relief-in-context check + demo).
   - Browser/three.js confirmed after explaining the tkinter-has-no-3D trade.
   - User workflow: after fold designation, non-fold geometry greys out, fold
     lines highlight; direction buttons (default up) then angle buttons
     (default 90) + custom angle entry; material selector (Sheet Metal / ACM,
     ACM thickness 3/4/6/custom); radius field default 2mm; "Visualize in
     browser" button. All interaction in tkinter; browser is read-only.
   - ACM: extrude → V-groove along fold lines proportional to angle → fold;
     rendered white.
   - Sheet-metal allowance/radius: T := R (derived, no separate field).
   - ACM radius semantics: residual exterior corner radius.
   - Persistence: session-only for V1 (sidecar JSON = V1.1 if re-assignment
     proves annoying in real use).
   - Sequencing: M7 after M5 and M6.
   - Geometry simplification (user idea, adopted): spacing math (tangent
     pullback d = R·tan((180−θ)/2)) instead of solid bend modeling; stitched
     outside skin via stock three.js primitives (one parameterized path, all
     angles) so the part doesn't look like separate pieces.

2. **Review loop 1** (three external persona sessions, OpenChamber):
   UI/UX expert 7/10, CAD professional 6/10, senior architect 7/10.

   ezdxf.edgeminer.Deposit/LoopFinder + ezdxf.edgesmith — kills the #1 risk);
   sign-vector classification instead of planar subdivision; the brief's
   "Forbidden: model changes" vs fold_props-in-ModelState contradiction
   resolved (M5 owns fold_eids; M7 adds fold_props — ADR text); brief's
   `three.module.js` wording struck (CORS-blocked on file://) — r147 UMD
   pinned with rationale; scene JSON in application/json script tag (`<`
   escaped); honest re-estimate.
