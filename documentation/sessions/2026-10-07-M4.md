## Plan (agreed with user before coding)

- **Confirm = enqueue, not apply.** M3's immediate-apply Confirm is
  repurposed per SPEC §5 ("toggle multiple corners → all pending changes
  previewed → single Apply All"). Queue = `PendingCorner` records
  (ADR-016(j)) in the UI layer, in click order.
- **M3 stays byte-identical.** The M4 seam is a `WorkflowUI` subclass living
  in `ui/apply_panel.py` overriding `apply()` (→ enqueue) and `radius()`
  (→ panel field), plus overlay hooks. M3's session stays closed; the M3
  golden harness path is untouched (it constructs base `WorkflowUI`).
- **Snapshot stack** (`model/snapshots.py`, ADR-001, unbounded depth, no
  deltas): load snapshot pushed at load time; Apply All pushes one deep-copy
  snapshot immediately before the first mutation. Undo = restore previous
  (multiple undos permitted; disabled — not crashed — at stack bottom).
  Second undo after one Apply All therefore lands on the load snapshot =
  original. Restore re-places any live in-flight preview (ADR-016(k)) so a
  stale preview can never confirm against the wrong model.
- **Revert-to-Original** = restore load snapshot + clear `flag_decisions`
  (ADR-009: stickiness is session-scope) + empty the undo stack (V1 has no
  redo; an undo past revert would be undefined) — the Revert button itself
  stays enabled.
- **Apply All driver**: for each queued pending in click order — re-place
  live (`place_corner` against current primitives + applied dogbones +
  current flag decisions + current R). ok → `Model.apply_corner`; refused →
  warn-and-skip (toast + preview-summary entry, engine string verbatim);
  new pending flags at re-place → warn-and-skip. Skipped corners are dropped
  from the queue (ISSUE-005 registers the shrink-R alternative for V1.1) and
  the workflow returns to PICK_EDGE1 cleanly.
- **Overlap (SPEC §4.4/§11.7)**: strict-with-EPS_COINCIDE against all
  pending+applied dogbones; tangent circles pass. Engine-verified already
  (`rules/engine.py` `_validate_inputs`, pinned string
  "OVERLAP: dogbone circle overlaps existing dogbone …(strict with
  EPS_COINCIDE; tangent circles are allowed)") — M4 consumes it verbatim at
  Apply-All re-place time; no engine change.

## Decisions (user-approved defaults + user rulings)

1. Any re-place refusal at Apply All (not just overlap) → warn-and-skip,
   engine string verbatim; the corner is dropped (V1; ISSUE-005 registers
   shrink-R for V1.1).
2. New pending flags surfacing at Apply-All re-place → warn-and-skip
   ("flag flow completes first" — the confirm-gate invariant applied to the
   batch).
3. Radius change re-places live previews; queued pendings adopt the current
   R at Apply All (WYSIWYG with ADR-016(k); mixed-tool parts apply in
   separate batches). Per-corner radius stays V1.1 (ISSUE-006).
4. Undo/Revert mid-pick → clean FSM restart to PICK_EDGE1 (no half-state).
5. Revert keeps the pending queue (eids are stable; re-placed at use).
6. `db_id` stays `db-<edge1>+<edge2>` (duplicate queue label is cosmetic;
   real arc eids are minted via `next_seq` at apply).
7. **User ruling — quick-pick tool buttons** (request 2026-10-07): the
   diameter field gains standard-size buttons in TWO columns, exact sets:
   English: 1/16", 1/8", 1/4" (dia; mm = 1.5875 / 3.175 / 6.35) |
   Metric: 2 mm, 3 mm, 4 mm, 6 mm, 8 mm (ascending). Buttons are
   presentation-only setters on the same diameter state as the free-entry
   field; the active size (incl. the 1/8" default) highlights. Free entry
   accepts plain floats in the current unit and simple fractions ("3/16").
   The button set is fixed constants (a user-editable bit list is V1.1
   scope creep — user approved).

   popups): the first M4 harness draft let corner3's cascade flag
   reach the base-class `messagebox.askyesno` modal — it blocked the
   headless drive and required user clicks to unstick. Fixed with M3's

   corner's `prompt_defaults`). The harness is fully headless again.

   `set_diameter_mm` / readout: `if self._unit_in:` tests the Var
   object (always truthy) — every reading was treated as inches
   (default 3.175 mm read as 80.645 mm). Fixed to `.get()` in all
   three sites. Caught by the app-level smoke probe.
3. Harness arithmetic: expected `db_id`s guessed un-promoted eids
   (actual: `db-promoted-B6+promoted-B3`); replaced with golden-center
   asserts. Per-click expected-state fallback replaced the unsound
   "state advanced" check (a silently missed second click never fell
   back). Undo-depth counts fixed after the load-seed ruling (the
   second phase's batch carries only its own snapshot).
4. Decision-3 correction: the original draft drove a mixed-R batch
   (corner3 R=3.175 + corner1 R=1.5875); queued pendings adopt the
   CURRENT R at radius change, so the batch must be same-R — the drive
