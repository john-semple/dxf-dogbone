## Root cause (two defects, same mechanism)

1. **Reported:** `FoldPanel.unbind_canvas()` called `canvas.unbind(seq)`
   for every fold-mode sequence. Tk's `unbind(seq)` deletes EVERY
   handler for the sequence, not just the caller's — so exiting fold
   mode (Esc / right-click / toggle) wiped the Viewer's pan handlers
   (`<ButtonPress-1>/<B1-Motion>/<ButtonRelease-1>`) and the corner
   workflow's pick/Esc handlers (`add=True` bindings from
   `ui/workflow.py`). Pan dead, corner picking dead: exactly the user
   report.
2. **Latent gate violation:** the shipped `add=True` composition means
   fold-mode clicks ALSO ran the corner workflow's `_on_left` (Tk runs
   every add=True handler; the M5b log's "fold mode consumes the click
   first" claim was wrong at the real-binding level). Designating a
   fold also started an edge-1 pick — violating the pinned gate
   "fold-mode does not start corner picks" outside the FSM tests.

**Why no gate caught it:** all fold tests are canvas-free FSM drives
(`test_ui_fold_fsm`), and `verify_gui --folds` drove the FSM directly
(`panel.fsm.exit()`), never `toggle_mode()`/`unbind_canvas()` through
real Tk bindings.

## Fix (ui/fold_panel.py)

- **Binding REPLACEMENT instead of add=True**: `bind_canvas` saves each
  sequence's prior script (`c.bind(seq)` returns it) and replaces it
  with the fold handler; `unbind_canvas` restores the saved scripts
  verbatim (`c.bind(seq, script)`), never `unbind()`. Corner workflow
  is suspended (not co-fired) while fold mode is ON.
- **Middle-drag pan in fold mode** (new): replacing B1 means L-drag no
  longer pans during fold mode, so B2 (middle button) press/motion/
  release handlers are added to the save/restore set — middle-drag
  pans, wheel still zooms (untouched `<MouseWheel>` binding), L-click/
  box designates.
- `FOLD_MODE_ENTER` (ui/messages.py) now mentions middle-drag pan.
- `math.hypot` import moved to module top (was a late import in
  `_on_release`).

## Decisions

1. Replacement over add=True: mode isolation is a binding-level
   property; the only correct suspension of the corner workflow while
   fold mode is ON is to not run its handlers. Tk offers no per-handler
   unbind (python-side funcid unbind exists but the app composition
   shares sequences), so save-script/restore is the mechanism.
2. Middle-drag pan: the CAD convention; keeps pan available in fold
   mode without re-implementing L-drag disambiguation (drag-vs-click
   threshold already occupies B1). Documented in FOLD_MODE_ENTER.
3. The M5b session log's decisions 5 ("add=True ... consumes clicks
   first") is superseded by this fix — logged here, M5b's log left
   untouched (session logs are append-only, never rewritten).
